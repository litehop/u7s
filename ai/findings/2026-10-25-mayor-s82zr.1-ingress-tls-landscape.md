# Ingress / L7 + TLS for u7s: landscape and measurements (2026-10-25)

**Recommendation: ship Traefik (Ingress + Gateway API, built-in ACME) as the first L7 controller, fronted by beep with no PROXY protocol or TPROXY; fix five apiserver CRD bugs found on the way before promising Gateway API; defer cert-manager.** Traefik is the only candidate that serves both Ingress and Gateway API, issues certificates itself, and is MIT-licensed with a current Gateway API v1.6 conformance report. Its 45-55 MiB footprint is mid-pack, and its one measured weakness (CPU) is a default (`RSA4096` ACME keys) that one flag removes. HAProxy and Caddy are leaner but are Ingress-only.

Everything below was measured on Spot e2-micro VPSes (1 GiB, shared core, Ubuntu 26.04, kernel 7.0) running u7s `v0.4.1-snapshot.1` from the mirror (`v0.4.2-snapshot.1` returned 404). One server VPS, one load-generator VPS in the same VPC. Unmeasured claims carry a source.

Latency (achieved/target rps; keepalive avg, p99; new-connection avg): Traefik 96/96, 4.5 ms, 20 ms, 86 ms; HAProxy 96/96, 3.2 ms, 7 ms, 14 ms; Caddy 96/96, 3.7 ms, 10 ms, 11 ms; Envoy Gateway 95/96, 5.2 ms, 17 ms, 9.6 ms; NGF 61-76/96, 57-89 ms, 380-490 ms, 190-225 ms (two runs).

Caveats: server certs differ (Traefik RSA4096 by default, HAProxy RSA2048 self-signed, others ECDSA P-256), so handshake latency and CPU are not comparable across rows. Traefik's `acme.keyType` defaults to `RSA4096` (docs, `traefik-acme.md`, v3.7.16); I did not rerun with `EC256`, so the CPU gap is a strong hypothesis, not a measurement. NGF's degradation was reproduced twice with 0% steal and was not diagnosed. Single runs, shared-core VPS: treat differences under ~20% as noise. The sampler itself cost ~20-30% of a core.

Chart defaults that break a 1 GiB node: HAProxy requests 250m/400Mi (its CRD-check hook pod requested 400Mi and stayed Pending, so `helm --wait` hung 10 min); Envoy Gateway's data plane requests 512Mi (unschedulable beside the controller's 256Mi until lowered).

## Q1. Ingress vs Gateway API

Both, in that order of effort. The Ingress API is frozen: "no further changes or updates", no removal planned (kubernetes.io Ingress concept page, `kubernetes/website` main, fetched 2026-10-25). Ingress-NGINX was retired March 2026 (retirement blog 2025-11-11; repo archived, `gh api` `archived=true`, pushed 2026-03-23); SIG Network recommends Gateway API. Gateway API is v1.6.3 (v1.6.0 released 2026-06-30; TCPRoute and UDPRoute graduate to Standard; v1.6 blog).

Conformance: the 1.37.1 suite has exactly two tests touching these APIs, `Ingress API` and `IngressClass API` (`test/conformance/testdata/conformance.yaml`, v1.37.1, lines 2006-2026), both API-surface only. No controller and no Gateway API are required. u7s serves `networking.k8s.io/v1` `ingresses` (+status) and `ingressclasses` (`state.rs`, `discovery.rs`).

Gateway API on u7s: the standard bundle v1.6.3 (10 CRDs + a ValidatingAdmissionPolicy) applies with `kubectl apply --server-side`; CEL rules reject an invalid Gateway (`hostname must not be specified for protocols ['TCP','UDP']`); a Traefik GatewayClass/Gateway/HTTPRoute reaches Accepted/ResolvedRefs/Programmed and routes HTTPS with a Secret-referenced cert. So the happy path works. The bugs below are the cost of adopting it.

### u7s apiserver defects found (all reproduced on the VPS; none filed)

1. **CR map fields are pruned to `{}`.** `prune_cr_unknown_fields` (`crates/apiserver/src/handlers/cr.rs:2545`) looks keys up only in `properties`; it never consults `additionalProperties`. A probe CRD with `additionalProperties: {type: string}` stored `{}`; with default strict validation the write is rejected `unknown field "spec.mapString.a"`. This silently drops `resources.requests/limits` in every operator CRD (Envoy Gateway's `EnvoyProxy` lost its resource settings). Highest severity.
2. **Gateway API's `safe-upgrades` VAP blocks every other CRD.** After installing the bundle, creating any CRD (even group `probe.example.com`) is denied with the VAP message. Bisect: any `has(object.metadata.<field>)` in a ValidatingAdmissionPolicy validation evaluates false/denies, even for present fields (`has(object.metadata.name)` alone denied on ConfigMaps; `true ? true : true` and `x != '' ? true : true` pass). Workaround: delete the VAP and binding.
3. **CEL cost estimator stricter than upstream.** Envoy Gateway's `SecurityPolicy` CRD is rejected ("estimated rule cost exceeds budget by factor of 1.258291x") though real Kubernetes accepts it; adding `maxItems` on the inner array changed nothing. Workaround used: strip `x-kubernetes-validations` from that CRD.
4. **`/apis` group discovery lists one version per group.** NGF's CRDs serve `v1alpha1` and `v1alpha2` in one group; `/apis/gateway.nginx.org` lists only `v1alpha1`, so helm fails `no matches for kind "NginxProxy" in version gateway.nginx.org/v1alpha2`. Workaround: create that object via the raw REST path.
5. **`additionalPrinterColumns` is dropped** on stored CRDs (`kubectl get gateway` shows NAME/AGE only). Cosmetic.

Also noted: `kubectl apply` of the 1.1 MB bundle without `--server-side` will exceed the annotation limit exactly as upstream.

## Q2. Controller choice

Ranked for u7s (1 GiB, Ingress needed by `mayor-lrqbx`, Gateway API desirable):

1. **Traefik** - only one-binary option covering Ingress, Gateway API, ACME, PROXY protocol; installed and issued certificates with only the VAP workaround (defect 2). Caveat: OSS ACME is single-instance (`acme.json`; HA needs Traefik Hub, docs `traefik-acme.md`), acceptable for 1-node targets.
2. **Envoy Gateway** - best Gateway API conformance story and the lowest data-plane CPU/handshake cost, but ~90 MiB, no Ingress, no ACME, and two apiserver defects (2, 3 above) must be fixed first.
3. **Caddy ingress** - leanest and the simplest ACME, but Ingress-only, stale (last release Jan 2025), and `spec.tls` hosts are excluded from automatic certs (`internal/caddy/global/tls.go`): ACME hosts must omit the `tls:` block, a surprising contract.
4. **HAProxy IC** - cheapest CPU, no Gateway API for HTTP, no ACME wiring, heavy chart defaults.
5. **NGF** - works, but needed a discovery workaround and measured poorly. 

Rejected: ingress-nginx (retired, no security fixes). Watch only: pure-Rust Pingora/agentgateway controllers (single-digit stars or AI-gateway focus; not evaluated beyond repo metadata).

## Q3. TLS termination and cert sourcing

**Terminate at the controller** (path routing needs plaintext). The cost is the known trade: HTTP routing XOR end-to-end encryption to the pod. Passthrough (TLSRoute / SNI TCP) stays available per route.

**Built-in ACME over cert-manager** for the default. Measured cert-manager footprint is ~100 MiB RSS (three pods) on top of the controller, and installing it wedged the 1 GiB node four times (unresponsive over IAP ssh for 8+ minutes each, cleared only by `instances reset`; cause not isolated, journal showed no OOM-kill lines; the controller restarted 8 times in 37 min with exit code 2). The ACME issuance through cert-manager was therefore **not measured**. cert-manager earns its place later for DNS-01/wildcards, Gateway API listener certs on controllers without ACME (Envoy Gateway, NGF), or non-HTTP workloads.

**Challenge types behind beep** (all measured with Let's Encrypt staging on `<vps-ip-dashed>.sslip.io`, which resolves without operator DNS):
- HTTP-01: passed (Traefik) end to end through the internet, GCP NAT, beep, pod; needs port 80.
- TLS-ALPN-01: passed (Traefik, Caddy); needs only port 443, handy where 80 is closed.
- DNS-01: not tested (needs a provider API credential). Required for wildcards; supported by Traefik (lego providers) and cert-manager.
beep is transparent to all three because it rewrites no payload and keeps the client IP; any challenge works if the VPS firewall opens 80/443 (the shared VPC allowed only IAP SSH, so I added a temporary `l7r-` tag-scoped rule).

**Where keys live and who reads them:** Traefik writes `acme.json` to a volume (I used `emptyDir`, so a pod restart re-issues; LE rate limits make a persistent hostPath/PVC mandatory; u7s has no default StorageClass). Ingress-referenced certs are Secrets; Traefik's ClusterRole grants `get/list/watch` on **all** Secrets cluster-wide (measured). cert-manager keeps keys in Secrets readable by anyone with namespace `get secrets`. Caddy ingress writes referenced Secrets to `/etc/caddy/certs` on the pod filesystem (source). Encryption-at-rest of Secrets in u7s was not examined.

## Q4. Client-IP transparency

**beep already delivers the real client IP to the controller pod at L3; the L7 hop needs `X-Forwarded-For`, not PROXY protocol or TPROXY.**
- Measured: a request from my workstation over the public internet reached Traefik and the backend saw `X-Forwarded-For`/`X-Real-Ip` = my public IP; from the second VPS the value was its internal 10.80.0.15. HAProxy showed `X-Forwarded-For: 10.80.0.15` on the internal path and Caddy the public IP; Envoy Gateway and NGF headers were not inspected. The controller's `Service` got `EXTERNAL-IP` = the node IP (`type: LoadBalancer`, eTP `Cluster`; NGF defaults eTP `Local`).
- beep's `externalTrafficPolicy: Local` cross-node fallback forwards "client IP preserved" (`manifests/README.md:34`), so a controller on a different node than the ingress node still sees the client.
- PROXY protocol v1 parsed correctly by Traefik with `trustedIPs` (injected `PROXY TCP4 203.0.113.9 ...` produced `X-Forwarded-For: 203.0.113.9`). It matters only if an external L4 balancer in front of the node masks the source; not needed behind beep. Per-controller support is cited in the table, not tested beyond Traefik.
- TPROXY is only needed if backend **pods** must see the real client at L3 behind the proxy. That would make the proxy bind to the client IP and force the backend reply back to the proxy's node, interacting with beep's symmetric Geneve return (beep's design doc lists the extra hook as deferred). Not tested; not recommended: HTTP apps get the IP from `X-Forwarded-For`. The September "Traefik ruled out because no `IP_TRANSPARENT`" premise only applies to that optional goal.
- Not tested: a `hostNetwork` controller bound to node ports 80/443 (no LoadBalancer Service at all), the simplest topology for 1-node VPSes.

## Measurement method

Server VPS (`l7r-a`, 1 GiB) ran u7s with one `whoami` pod, flannel, kube-proxy, CoreDNS, beep; one controller at a time, installed with helm 4.3.1 (helm run on the VPS, `--no-hooks`/`--skip-crds` where noted). Per-container RSS and CPU read from the container cgroup (`memory.stat` anon + file_mapped, `cpu.stat usage_usec`) every 4-8 s by script; load from a second e2-micro in the same subnet with `hey` against the node's internal IP. Spot preemption stopped both VPSes twice (04:09Z, 05:01Z); the first controller's numbers predate a reboot, Caddy's idle figure moved 28 to 42 MiB across one, so ranges are given. Raw logs were in a gitignored `temp/` directory.
