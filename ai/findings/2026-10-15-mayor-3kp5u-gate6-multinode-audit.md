## Item 1 -- distribution origin

- **Current state.** `deploy/get-u7s/get-u7s.yaml` is an nginx reverse proxy (Ingress host `u7s.dekiru.tech`, line 190) that streams GitHub release assets. Probed 2026-10-15T01:50Z: `https://u7s.dekiru.tech/install.sh` returns 404; `https://u7s.dekiru.tech/v0.3.0-snapshot.1/install.sh` returns 200. `deploy/get-u7s/README.md` "Open items" says the same (`latest` skips prereleases; all releases are prereleases; newest is v0.3.0-snapshot.1, 2026-09-16). `README.md:22` already advertises the unpinned URL, so the documented one-liner fails today. The release workflow (`.github/workflows/release-tarball.yaml`) bakes `DEFAULT_TARBALL_URL` into `install.sh`; the tarball is 87.6 MB (x86_64 only, `build-release-tarball.sh:10`).
- **Settled.** `docs/decisions/distribution-hosting-shape.md` (self-hosted streaming proxy, no redirect, caching deferred); `docs/decisions/install-script-ux.md` (curl|bash shape; domain left open there, now chosen).
- **Open.** (a) First stable `vX.Y.Z` tag. (b) `@follow_hop3` has no error_page, so a 4th GitHub hop leaks a 3xx to the client (README open item). (c) Authenticity: `fetch_tarball` (`install.sh:218`) verifies a `.sha256` sidecar fetched from the same origin as the tarball, which catches truncation but not a compromised origin; the script itself is `curl | sudo bash`, so it is the trust root anyway. (d) The joining node downloads the full tarball although it uses only `kubelet` (`install.sh` worker mode stages kubelet alone); not measured, likely a small saving since kubelet is the bulk.
- **Options.** A: cut one stable tag, fix hop3, stop. B: A plus a detached signature (minisign/cosign) verified in `install.sh` against a pubkey baked into the script -- adds a dependency on the host and still roots in the script's own transport. C: A plus a worker-only tarball. Recommend A; B only if the operator wants a defense against origin compromise (D1).
- **Security.** Proxy is a narrow-pattern relay (README warns against loosening it into an open GitHub relay). TLS is the only authenticity today.
- **Verify.** Existing `scripts/test-install-checksum.sh` covers the checksum path. Add a curl check of `/install.sh` returning 200 after the tag; end-to-end proof is the fresh-VM run in item 2's e2e (open bead mayor-ed4dv covers the single-node variant).

## Item 2 -- multi-node join

- **Current state.** `install.sh:25-41` header, `mint_join_token` (`:318`), `join_cluster` (`:381`). Flow: on the control plane, `--mint-join-token --node-name N --node-ip IP` appends `secret,system:bootstrap:<id>,<uid>,system:bootstrappers` to `$STATE_DIR/token-auth-file`, **restarts u7s-apiserver** (token map is load-once, `auth.rs:133` `load_token_file`), signs a kubelet serving cert (10-year, IP SAN) with `ca.key`, and prints one base64(JSON) artifact `{caCert, bootstrapToken, servingCert, servingKey}`. On the worker, `--join <url> --token <artifact>` writes the CA, generates a client key, submits a `CertificateSigningRequest` (signer `kubernetes.io/kube-apiserver-client-kubelet`) with the bootstrap token, waits for KCM's builtin csrapproving/csrsigning (`kube-controller-manager --cluster-signing-cert-file=ca.pem --cluster-signing-key-file=ca.key`, `install.sh` KCM unit) and writes a kubeconfig with the node's own x509 identity. RBAC: `system:node-bootstrapper` and `...:nodeclient` bound to `system:bootstrappers` (`crates/apiserver/src/lib.rs:2005-2067`). Kubelet self-renews the client cert (`rotateCertificates: true`, `install.sh:306`). Node scoping: `crates/apiserver/src/node_authz.rs`. Re-join on a joined worker is refused (`install.sh:512-530`, tested in `scripts/test-install-logic.sh:683-693`). Flannel (vxlan) and kube-proxy are vendored DaemonSet manifests (`manifests/`), node-ipam hands out pod CIDRs.
- **Settled.** `docs/decisions/install-script-ux.md` Consequences: join mode = first node address plus shared token, additive, never on the zero-arg path. `docs/decisions/upstream-component-shipping-shape.md`: unmodified upstream KCM/kubelet; kube-proxy in-cluster. `docs/decisions/systemd-install-contract.md`: units per binary. No ADR fixes the artifact shape or token lifetime; those were decided in closed beads (mayor-iuetx, mayor-wmmqm, mayor-yocic, PR #1354), not in `docs/decisions/`. Roadmap's "join-token settled in ADR" is therefore slightly overstated: the *shape* is in install-script-ux, the *mechanics* are only in bead history.
- **Gaps found (all verified in source).**
  1. Tokens never expire and are never consumed. The `install.sh` header and comments call them "single-use"; `load_token_file` has no expiry field and nothing deletes entries (grep of `crates/apiserver` finds no consumer-side removal). Any leaked artifact is a permanent credential for `system:bootstrappers`, which (by deliberate simplification, `lib.rs:2048-2058`) may create client CSRs for any `system:node:<name>` CN. With KCM approval that is a node identity for an arbitrary name, bounded only by the node authorizer's graph scoping.
  2. Every mint restarts the apiserver (brief control-plane outage, all watches dropped).
  3. The artifact carries a kubelet serving **private key** and is passed as a CLI argument (visible in shell history and `ps`). Node name and IP must be known at mint time, so one token cannot join N nodes.
  4. The apiserver serving cert SAN is only the advertise address (`tls.rs:447-466`); the worker must join via exactly that address.
  5. Flannel's `--iface` is baked from the *control plane's* `--iface` (`install.sh` sed of `flannel.yaml`; `manifests/flannel.yaml:10,160-161`), with a physical-NIC regex fallback. A worker using a different `--iface` (the WireGuard case the north star names) gets kubelet `--node-ip` right but flannel falls through to the regex and will not select `wg0` unless the mesh interface name is uniform on every node.
  6. The conformance rig does not exercise any of this: `scripts/conformance/add-node.sh` -> `lima-start.sh:434-445` copies the shared admin kubeconfig and the CA into the VM; apiserver runs on the host. The only coverage of `install.sh` join is the refusal case in `test-install-logic.sh` plus one manual live test recorded in PR #1354. There is no automated two-VM `install.sh` e2e.
- **Upstream comparison (cached in `temp/research/`, gitignored).** kubeadm: bootstrap tokens are Secrets `bootstrap-token-<id>` in kube-system with `expiration` (default 24h) and `usage-bootstrap-authentication`, authenticated by the apiserver at request time (no restart) and reaped by KCM `tokencleaner` (`--controllers=*,tokencleaner`; off by default) (`kubeadm-bootstrap-tokens.md:27-66,95-137`). Joining node pins the CA by hash (`--discovery-token-ca-cert-hash`). k3s: long-lived server/agent token, `K10<ca-sha256>::<secret>` secure format, CA hash pin checked before credentials are sent (`k3s-token.md`), plus optional bootstrap-type tokens. u7s's artifact embeds the full CA cert, which is a stronger pin than either hash.
- **Options (u7s-shaped).**
  - 2a, S: stop printing the artifact in the command line; read it from `U7S_JOIN_TOKEN` or a file/stdin; correct the "single-use" wording until it is true.
  - 2b, M: apiserver authenticates `bootstrap.kubernetes.io/token` Secrets (id.secret, expiration, groups) -- the kubeadm shape -- and enable `tokencleaner` in the KCM unit's `--controllers`. Mint becomes `kubectl create secret` equivalent: no restart, default TTL (e.g. 1h), `--mint-join-token` stops needing `ca.key` for tokens. Keep `token-auth-file` for nothing else, or delete it (pre-alpha, delete).
  - 2c, M: remove node name/IP from mint. Worker already knows its IFACE_IP and name; make the artifact cluster-wide `{caCert, token}` and have the worker obtain its kubelet serving cert via a `kubernetes.io/kubelet-serving` CSR. KCM does not auto-approve serving CSRs, so u7s would add a narrow auto-approver (CN `system:node:<n>`, SAN IP == requester's reported address, requester is that node). Removes the transported private key and the 10-year serving cert; kubelet currently has `RotateKubeletServerCertificate=false` (feature-gate list in `install.sh`), so that gate must flip.
  - 2d, S: per-node flannel interface via the `flannel.alpha.coreos.com/public-ip-overwrite` Node annotation set by the worker after join (node authorizer permits self-patch), instead of the baked `--iface`. Needs verification against the pinned flannel version before committing to it.
  - 2e, M: automated two-VM e2e (see Verify). Recommended before 2b/2c so hardening has a regression net.
- **Security.** Token lifetime (gap 1) is the main issue; CA key never leaves the control plane in this flow (good: only `ca.pem` is shipped); serving key transit (gap 3) and CLI exposure are secondary. Client cert rotation is already automatic (KCM default signing duration, kubelet `rotateCertificates`).
- **Verify.** New script (e.g. `scripts/e2e-install/two-node.sh`, name TBD) on two fresh Ubuntu Lima VMs running the real `install.sh` from a built tarball: node A default install, mint, node B `--join`; assert `kubectl get nodes` shows both Ready, pod-to-pod and ClusterIP across nodes, `kubectl logs`/`exec` against a pod on B (apiserver dials the node InternalIP:10250 via `node_address`, `handlers/proxy.rs:60-90`, no per-node port map needed on a real network), `kubectl get csr` shows the join CSR Approved+Issued. Negative cases for 2b: expired token rejected, deleted token rejected. Extends mayor-ed4dv.

## Item 3 -- CA trust / rotation

- **Current state.** `tls.rs:133-241` `load_or_generate_ca`: one flat CA, persisted `ca.key` (PEM, 0600) and `ca.crt` (DER), CN `u7s-ca-<random>`; no `not_before/not_after` set anywhere in `tls.rs`, so rcgen defaults apply (effectively non-expiring; unverified by running, from rcgen's documented defaults). Dedicated front-proxy CA (`tls.rs:404,562`). `ca.key` is plaintext on the control-plane disk and readable by KCM (root) for signing. Join delivers only the CA cert. `kube-root-ca.crt` seeded from the CA (`lib.rs:229,3809`). No TLS hot reload, no HA (single apiserver).
- **Settled.** Trust bootstrap: yes (CA in artifact; closed bead mayor-wmmqm decided rotation tooling is deliberately not built because nothing requires it). Prior research bead mayor-xk0pa ranked: minimal CA-in-token + kubeadm-style manual dual-bundle runbook first. No ADR exists for rotation.
- **Upstream.** k3s ships `certificate rotate-ca` (`temp/research/k3s-token.md` covers only token/hash); kubeadm has no built-in CA rotation, only a documented manual dual-trust-bundle procedure (`kubeadm-certs.md`); k0s admits rotation lacks automation (per mayor-xk0pa).
- **Options.** A (S): document "CA compromise = rebuild the cluster and re-join nodes"; keep as is. B (S): make all trust consumers tolerate a PEM bundle (artifact `caCert`, kubeconfig `certificate-authority-data`, `kube-root-ca.crt`, KCM `--root-ca-file`) so a future rotation is possible without re-architecting; no tool. C (L): a `rotate-ca` subcommand (k3s-shaped); needs apiserver TLS reload and a coordinated worker step, in tension with the small-surface philosophy.
- **Security.** Non-expiring CA means no scheduled cliff but also no forced hygiene; compromise recovery is the only reason to rotate. Key handling to decide: keep `ca.key` plaintext 0600 on the single control-plane node (current), no HSM/KMS (out of scope for 1 GiB VPS).
- **Verify.** For B: unit test that a two-cert bundle verifies leaf certs from either CA in the kubeconfig/artifact consumers; extend the two-node e2e to join with a bundle artifact.

## Item 4 -- metrics-server

- **Current state.** Not shipped by default (`docs/decisions/upstream-component-shipping-shape.md`: excluded because Conformance does not need it; HPA users apply it themselves; `manifests/README.md` repeats this). The dev harness applies `scripts/conformance/manifests/metrics-server.yaml` (v0.9.0, 227 lines) in `scripts/conformance/run-all.sh:453-454`, with `--kubelet-insecure-tls` and a `memory: 200Mi` / `cpu: 100m` request (lines 168, 192-194). The apiserver already has API aggregation (`handlers/aggregation.rs`, APIService availability reconcile `lib.rs:491-499`) and seeds RBAC mentioning `metrics.k8s.io` (`lib.rs:2610`).
- **Settled.** ADR: opt-in, documented, not hidden. Reversing it needs a new ADR.
- **Why `--kubelet-insecure-tls` may be unnecessary in a real install.** `install.sh` signs kubelet serving certs with the cluster CA (IP SAN), unlike the harness. Whether metrics-server verifies them with the pod's in-cluster CA without extra flags is *not verified here*; needs one live run.
- **Options.** A (S): ship `metrics-server.yaml` in the tarball outside the auto-apply folder (e.g. `/usr/share/u7s/optional/`), `install.sh` prints the one-line `kubectl apply -f` hint; drop the insecure flag after verification; keep ADR. B (M): default-install it; needs ADR reversal and a RAM measurement against the 128 MiB control-plane budget (excludes workloads, but a 200Mi request on a 1 GiB VPS is a real cost) and likely a lower request. Recommend A.
- **Security.** Insecure TLS to every kubelet from an in-cluster pod is acceptable only in the lab; production manifest must not carry it.
- **Verify.** After item 2e exists: apply the manifest on the two-node install, assert `kubectl top nodes` lists both nodes and a CPU-target HPA reports `ScalingActive=True` (the existing non-Conformance HPA e2e is the model).

## Operator decisions

1. **D1: distribution authenticity.** (a) Stable tag + hop3 fix only; (b) add detached-signature verification in `install.sh`; (c) also publish a worker-only tarball. Trade-off: (b) adds a verification dependency and key management for little gain while the script itself is the trust root. Recommend (a).
2. **D2: join token model.** (a) Keep static token-auth-file, only fix CLI exposure (2a); (b) Secret-backed bootstrap tokens with TTL + tokencleaner (2b); (c) 2b plus cluster-wide artifact and serving-CSR auto-approval (2c). Trade-off: (c) is the best UX (one token, no node IP at mint) but adds an apiserver-side approver. Recommend (b) now, (c) as a follow-up.
3. **D3: CA rotation.** (a) Document rebuild-on-compromise only; (b) a + bundle-tolerant consumers; (c) build `rotate-ca`. Trade-off: (c) is L and grows the CLI surface against the north star. Recommend (b). Also: keep the non-expiring CA, or bound it (creates a cliff that then requires rotation)? Recommend keep.
4. **D4: metrics-server.** (a) Keep ADR, ship an optional manifest in the tarball; (b) install by default (ADR reversal, RAM cost). Recommend (a).
5. **D5: what "agent-facing install" means.** Worker/agent node (already item 2), AI-agent-consumable install, or something else? Needed before any sizing beyond the S estimate above.
6. **D6: per-node interface for the WireGuard case.** Accept "mesh interface name must be uniform across nodes" (zero work, document it), or implement the per-node flannel annotation (2d, S, needs verification). Recommend implementing 2d, since a non-uniform `--iface` silently picks the wrong flannel interface.
7. **D7: ADR housekeeping.** Record the join mechanics (CSR flow, artifact shape, token lifecycle) in `docs/decisions/` once D2 lands; today they live only in closed beads.
